# Process documentation

Create only the requested artifact. Preserve source roles, actions, conditions, and status. Before drafting, identify audience, scope, format, and the end point the supplied process actually documents.

For each step use a clear action, responsible role when known, required input, and documented outcome. Keep unsupported permissions, deadlines, approvals, and exceptions out of the current-state procedure; mark material dependencies as “to confirm.” Separate current process from proposed changes. Do not claim a draft is approved, published, or validated.
