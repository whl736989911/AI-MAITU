# 知识库个人资料整理：双文档设计与开发计划

本文件替代此前的文件加工级别方案。当前实现不增加文件等级，也不为每个文件自动创建两份文档。

## 1. 用户确认的范围

- 在知识库的「资料整理」界面，显式选择需要整理的文件或文件夹。
- 每个选择项独立创建整理集和两份 Markdown 文档。父文件夹与显式选择的子文件分别计算、分别配置，互不合并。
- 自动包含的后代文件属于文件夹整理范围，不会因此各自新增整理集。
- 关键词默认空白，由用户自行设置；不自动继承其他整理集或已有个人检索规则的关键词。
- 原文件仍是事实来源。整理文档用于快速找到内容和原文位置，不代替来源核验。

## 2. 两份文档及内容归属

| 文档 | 写入条件 | 内容 |
| --- | --- | --- |
| `keyword-index.md` | 用户配置关键词，已有或显式生成的源索引中存在命中 | 原文命中分片、关键词、文件名、来源路径、文档与分片 ID、位置、源版本 |
| `reading-index.md` | Agent 的 `read_knowledge_segment` 或同源 HTTP 段落读取成功核验原件 | 实际读取分片的摘录式摘要、原文摘录、位置与版本；已归关键词文档的分片只记录对应分片索引，不重复正文和摘要 |

同一整理集以源文档 ID、源版本和分片 ID 识别条目，两份文档是同一组来源条目的不同视图，不分别维护两套事实。关键词修改后重新归类：已读内容可以转入关键词视图，取消命中后仍保留在阅读视图。

文件名或路径命中单独标为定位线索，不复制不相关正文，也不冒充正文证据。各来源的分歧保留其独立出处，不自动拼成一份统一结论。原文核验不能证明不同原件彼此一致。

阅读摘要是原文的摘录式预览，最长 320 字符，不是模型生成的综合结论；未核验的搜索片段、Agent 推测和未实际读取的正文不会作为阅读记录写入。

## 3. 身份、范围和存储

整理集属于创建用户，同一用户的不同 Agent 可以在其本轮绑定的知识库范围内复用；其他用户及管理员不会因管理员身份而读取别人的个人整理集。

文件夹按完整路径边界包含后代，`legal` 不包含 `legal-extra`。文件、文件夹均绑定稳定的公开文档 ID：改名保留对应关系；删除后同路径新建文件不会自动接管旧整理集。

存储位置：

```text
<OCTOP_HOME>/knowledge-collections/<owner_user_id>/<collection_id>/
  keyword-index.md
  reading-index.md
```

这是平台数据目录，不是 Git 仓库的 `docs/`，也不是源知识库目录或 Agent 工作区。界面展示实际路径。数据库保存整理集与源条目对应关系；Markdown 是可重建的派生视图。

新增 SQLite/PostgreSQL 成对迁移 `040_knowledge_collections.sql` / `040_knowledge_collections.pg.sql`，包含整理集、来源条目及成员身份表。原件解析仍复用现有索引，不为每个整理集重复做 OCR 或单独维护向量模型。

## 4. 与项目现有能力的结合

### 检索与读取

1. `KnowledgeService.search` 先检索当前用户整理文档对应的索引，再由现有原文索引补足候选。
2. 工具与网关保持整理结果优先；重叠选择仍分别生成文档，但同一原文分片不会占据多个检索名额。
3. 结果携带原文身份、源版本与位置；搜索命中本身不等于证据。
4. `read_knowledge_segment` 继续核验实际来源内容摘要和当前 ACL，成功后把读取记录写入所有包含该文件的当前用户整理集。

沿用本轮 `knowledge_base_ids`、库/文件权限和个人排除规则，不扩大 Agent 的挂载范围。显式生成不能绕过管理员关闭知识功能，也不能自行开启 OCR、模型或嵌入配置。

已有「个人检索设置」决定检索候选及排除范围；新整理集的关键词决定两份整理文档的内容归属。两项配置不自动相互覆盖。

### 更新与失效

- 上传替换、正文修改、改名、删除、重新索引和数据源扫描接入整理视图更新。
- 源版本变化后，旧版本的关键词摘录和已读记录不再作为当前内容返回；新版本的阅读记录需要重新核验读取。
- 当前 ACL 与个人排除规则参与检索检查；没有权限时不返回旧缓存摘录。
- 后台刷新不自行解析文件；配置空关键词和创建整理集不触发全目录加工。
- 同一进程内按整理集串行化读取记录与重建，Markdown 采用临时文件原子替换；生成原件索引时不持有整理集写入锁。

### 备份与删除

系统备份的 `include_knowledge` 同时控制原知识索引及 `knowledge-collections/`；恢复时一并恢复。删除整理集只删除其派生文档及记录，不删除原文件，也不影响其他独立整理集。

HTTP 契约见 [API 文档](api.md#personal-two-document-collections)。
