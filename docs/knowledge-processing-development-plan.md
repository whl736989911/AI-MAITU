# 知识库原件访问与双文档资料整理

本设计替代此前的个人关键词整理与检索策略。整理集沿用源知识库、文件夹和文件的权限，不再是创建者私有的检索规则。

## 1. 原件是最低保障

- Agent 只访问本轮挂载、当前用户有权读取的知识库及原件，不要求文件已完成索引，也不要求配置向量模型。
- 先浏览和定位文件；存在相关整理集时，先读取专题成果与阅读积累，再按出处读取原件的具体位置。
- 按需提供文本行、PDF 页、工作表行以及图片。图片交付给模型不等于已识别；视觉解读单独记录为模型观察，不能冒充核验过的文字。
- 原件可通过工作区接口取得并用于生成材料。共享专家或功能的工作区可能被其他使用者读取，因此原件导出必须在已完成初始化的主会话中确认，绑定具体文件和版本，不能通过会话免审批或子任务绕过；源权限不能追溯控制已导出的副本。
- 当前复用原件读取和已有格式解析，不新增 MarkItDown、WeKnora 或整库导航文档。格式转换只能作为辅助，不能替代原件、权限和出处。

主动整理仅处理原件读取器支持的文件格式，复用现有知识库格式表和按行读取的文本格式；`Thumbs.db` 等不支持格式自动跳过，不计入整理覆盖统计中的待处理或失败。不删除原件、不改变访问权限，仍可浏览和按权限取得原文件。此前这些格式留下的专题错误也不再参与当前整理视图。支持格式的文件若损坏、加密、超出读取限制或缺少解析依赖，仍按实际失败提示，不能伪装为已读或已整理。

图片交付保留每个图片片段 8 MiB 的内部上限，在 Base64 编码前检查。这不是上传、存储、目录总量或网络带宽限制，也不代表模型提供商的实际请求上限；8 MiB 的二进制图片转成 Base64 后约为 10.67 MiB，尚未计入其他请求内容。

- 未超限的原始图片保持原有字节和格式；超限的可解码图片及 Office 内嵌图片改为一张整图概览和多张局部 PNG。概览最长边不超过 1024 像素且不放大；局部块最大 1024 × 1024 像素，相邻块至少重叠 64 像素，无损覆盖原图，不改写原件。PDF 沿用现有的分页、限尺寸渲染路径。
- 图片交付按现有范围参数分页，每次最多四个片段。主动整理对每个片段单独调用模型，再以有界文本分批汇总；不能把所有图片块一次塞入模型请求。单份原件的主动视觉整理最多处理 257 个图片片段（包括概览和内嵌图片）；超出安全范围或解码失败须明确报告未完成，不能静默截断。
- 每块记录原文件版本、整图尺寸和矩形区域。坐标使用 EXIF 方向校正后的显示像素；Office 图片同时保留嵌入资源位置。同一段解读即使文字相同，只要来源区域不同，也分别留存证据。
- 概览用于全局布局，局部块用于细节；汇总去除重叠造成的重复，同时保留冲突、不确定性及未读部分。模型不支持图片或中途失败时保留已获得的观察并标明待视觉处理，不能伪装为成功。模型图片解读始终属于待核验观察，不等同于准确 OCR。

## 2. 创建与主动整理

- 每个显式选择的文件或文件夹创建独立整理集；父目录与子文件可以同时选择，自动包含的后代不各自创建整理集。
- 创建只登记名称、范围和自由提示词，不读取、解析或索引整个文件夹。提示词可留空，此时仍能沉淀阅读积累。
- 用户点击「整理」才按提示词处理范围内当前可读原件；没有提示词时不能运行专题整理。
- 修改提示词使旧专题结果失效；部分文件不可处理时保留已成功结果，并报告部分完成和失败覆盖，不伪装全部完成。
- 同一整理集正在整理时拒绝重复启动，返回 `409 KNOWLEDGE_COLLECTION_GENERATING`。

## 3. 两份 Markdown 与出处

| 文档 | 内容与更新方式 |
| --- | --- |
| `topic-index.md` | 根据用户提示词形成专题成果；保留来源引用与覆盖状态。后续实际阅读发现的补充、修正和不确定性用于核对已有成果，不把旧版本结论继续标为当前事实。 |
| `reading-index.md` | 积累实际读取的内容及图片观察；记录具体出处、原件版本和证据身份。仅浏览目录、获取元数据或导出原件不会冒充已读正文。 |

每条证据保留知识库相对路径、稳定文件 ID、源版本以及可定位的行、页、工作表或嵌入图片位置。模型整理与原文证据分开；冲突、不完整和待核验状态必须显式保留。

同一次原件读取向所有包含它的整理集同步积累，包括上级目录整理集和文件整理集，不重复解析原件。`legal` 不包含相邻的 `legal-extra`。普通阅读不自动重新扫描整库。

## 4. 权限与存储

- 整理集可见性由目标原件当前权限决定；混合文件夹的派生内容按每位调用者可读的源文件过滤。
- 修改名称、提示词、删除或主动整理要求目标原件写权限或知识库管理权限；普通读取可自动积累证据。
- 文件夹权限逐级收窄，单文件明确授权仍沿用既有例外规则，不能突破库级权限。撤销后不返回此前缓存的正文。
- 文件改名保持稳定身份；删除后在原路径创建的新文件不会自动接管旧整理集。
- Markdown 是可重建的调用者权限过滤视图，存放于 `<OCTOP_HOME>/knowledge-collections/<collection_id>/<user_id>/`，不写入源目录。系统知识备份仍包含整理数据。
- 数据库迁移 `041_knowledge_prompt_collections.sql` / `041_knowledge_prompt_collections.pg.sql` 保存原件证据和专题结果，迁移旧提示词及匹配源版本的阅读记录，移除旧个人检索规则和关键词归类数据表。

## 5. 知识库页面授权

| 范围 | 边框 | 页面标识 |
| --- | --- | --- |
| 全公司 | 绿色 | 公司 |
| 部门 | 蓝色 | 实际部门名称 |
| 个人 | 灰色 | 个人 |
| 单独授权 | 紫色 | 单独 |

页面显示有效权限及继承来源，区分读取、编辑与授权管理。知识库所有者和系统管理员可在这里选择用户、部门或角色授权，不要求先拥有用户管理模块；变更继续走原有审批和审计。共享设置保留其他资源和审批，不再提供知识库文件配置入口。

旧个人检索设置、关键词策略和专用接口已移除。普通文件名定位、已有全文/可选向量索引以及历史引用展示不因此删除。

HTTP 契约见 [API 文档](api.md#source-authorized-two-document-collections)。
