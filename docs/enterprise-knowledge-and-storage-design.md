# 企业单一知识库与外部文件夹数据源设计

> 状态：待开发设计
>
> 关联文档：[定制化功能权限与组织管理设计](./customized-permissions-and-org-management.md)
>
> 目的：定义企业知识库、外部文件夹数据源、文件权限、提取模板、增量同步、多格式解析和企业级存储资源池的后续开发方向。

## 1. 核心结论

知识库不设计为“用户新建多个知识库”，而是采用企业级单一知识库：

```text
企业
└── 企业知识库
    ├── 数据源文件夹
    ├── 文件索引
    ├── 摘要与关键词
    ├── 自定义提取结果
    ├── 全文索引
    └── 可选向量索引
```

核心规则：

- 每个企业只有一个逻辑知识库。
- 用户不能新建第二个知识库。
- 一个企业知识库可以绑定多个本地、SMB 或 NFS 文件夹。
- 原始文件继续保留在外部文件夹，平台保存索引和派生结果。
- 用户能看到和搜索到的内容由企业、部门、用户和角色权限决定。
- 知识库读取权限和编辑权限分离。
- 文件变化采用“事件触发 + 定时扫描 + 手动同步”的混合机制。
- 向量模型是可选的语义检索能力，不负责文件解析和知识整理本身。

如果系统是单企业部署，则平台只有一个企业知识库；如果系统未来支持多企业，则每个企业拥有独立的逻辑知识库和数据权限边界。

## 2. 与现有架构的差异

当前实现更接近：

```text
用户上传文件
→ 文件复制到平台目录
→ 解析和索引
→ 用户选择知识库使用
```

目标实现是：

```text
本地/SMB/NFS 文件夹
→ 数据源连接器
→ 文件扫描与变化检测
→ 文件类型解析
→ 摘要、关键词和结构化字段提取
→ 全文索引
→ 可选向量索引
→ 权限过滤后的搜索和对话引用
```

因此，后续改造不是单纯增加一个上传入口，而是把知识库改造成“企业文件数据源索引服务”。

现有 `knowledge_bases` 权限标识可以暂时保留以兼容旧用户配置，但语义调整为“企业知识库访问/管理权限”，不再表示用户可以创建多个知识库。

## 3. 数据模型

建议将知识库相关对象拆成以下几类：

### 3.1 企业知识空间

```text
EnterpriseKnowledgeSpace
```

表示一个企业的唯一逻辑知识库。它不再有“用户所有者”概念，主要关联企业、状态、默认搜索策略和全局统计信息。

### 3.2 数据源

```text
KnowledgeSource
```

表示一个本地或网络文件夹连接，包含：

- 所属企业。
- 连接类型：`local`、`smb`、`nfs`。
- 地址、共享名称和根目录。
- 加密后的凭据引用。
- 只读设置。
- 包含/排除规则。
- 扫描间隔。
- 连接状态。
- 最近扫描时间和最近成功同步时间。

### 3.3 文件索引

```text
KnowledgeFile
```

保存源文件的索引和处理状态：

- 数据源 ID。
- 相对路径和文件名。
- 扩展名、MIME 类型和检测到的真实类型。
- 文件大小、修改时间和内容 hash。
- 解析器版本。
- 当前模板和模板版本。
- 处理状态。
- 删除或不可访问状态。
- 原文件定位信息，例如页码、工作表和段落。

### 3.4 派生内容

```text
ExtractionResult
KnowledgeChunk
KnowledgeEmbedding
```

分别保存：

- 正文和统一文档结构。
- 摘要、关键词和自定义字段。
- 文档分块。
- 全文索引。
- 可选向量索引。
- 生成所使用的模板、模型、解析器和文件版本。

原始文件是外部数据源的事实来源，平台不默认复制原始文件。

## 4. 数据源连接与安全

第一阶段支持：

- 本地服务器目录。
- SMB 共享目录。
- NFS 共享目录。

平台直接连接 SMB/NFS，而不是只依赖操作系统预先挂载的路径。连接配置需要包括：

- 服务器地址。
- 共享名称。
- 根目录。
- 用户名、密码或密钥。
- 连接协议参数。
- 只读模式。

安全要求：

- 密码和密钥必须加密保存。
- API 不返回明文凭据。
- 日志不能打印凭据、完整连接字符串或授权头。
- 数据源默认只读，写入能力必须显式授权。
- 平台连接账号拥有读取能力，不代表所有平台用户都拥有访问能力。
- 连接测试、扫描和文件读取都需要记录审计信息。

## 5. 权限模型

知识库内部权限不再围绕多个知识库之间的共享，而是围绕企业知识库内的资源：

```text
企业知识库
└── 数据源
    └── 文件夹
        └── 文件
```

### 5.1 授权主体

支持以下授权主体：

- 企业。
- 部门。
- 用户。
- 角色。

部门授权默认包含本部门及所有子部门。

### 5.2 读取和编辑分离

读取权限控制：

- 是否可以搜索文件。
- 是否可以查看摘要和关键词。
- 是否可以查看结构化字段。
- 是否可以查看原文件或原文件链接。
- 是否可以在对话中使用检索结果。

编辑权限控制：

- 是否可以添加或删除数据源。
- 是否可以修改目录权限。
- 是否可以绑定提取模板。
- 是否可以触发同步和重新提取。
- 是否可以管理模板。

搜索必须先过滤权限，再执行检索：

```text
用户身份
→ 企业范围
→ 数据源权限
→ 目录/文件权限
→ 搜索和摘要
→ 原文件访问
```

不能先搜索整个企业知识库，再在结果展示阶段过滤，否则摘要、引用和搜索片段可能泄露无权访问的内容。

### 5.3 目录权限继承

推荐采用目录继承：

```text
共享目录
├── 公司制度       → 全企业可读
├── 财务资料       → 财务部门可读
├── 人事资料       → 人事部门可读
└── 技术资料
    ├── 产品A       → 产品A小组可读
    └── 产品B       → 产品B小组可读
```

规则：

- 上级目录权限默认继承到子目录。
- 子目录可以追加权限或收紧权限。
- 文件默认继承所在目录权限。
- 单个文件可以增加额外授权。
- 企业管理员管理本企业范围。
- 部门管理员管理本部门及子部门范围。
- 员工只能访问被授权的文件。

底层 SMB/NFS 凭据权限和平台内部业务权限是两套权限，必须分别校验。

## 6. 文件类型与统一解析

向量模型主要接收文本或结构化文本，不能直接处理 PDF、Word、Excel、图片等文件。统一流程为：

```text
文件类型识别
→ 对应解析器/OCR/转写器
→ 统一文档结构
→ 摘要、关键词和自定义字段提取
→ 文本分块
→ 全文索引和可选向量索引
```

支持矩阵：

| 文件类型 | 处理方式 | 后续检索 |
| --- | --- | --- |
| TXT、MD、HTML | 直接读取文本 | 全文和向量 |
| PDF | 提取文本；扫描 PDF 使用 OCR | 全文和向量 |
| DOCX | 提取正文、标题、表格和备注 | 全文和向量 |
| DOC | 转换为 DOCX/HTML/TXT 后解析 | 全文和向量 |
| XLSX、CSV | 保留表头、行列和单元格关系 | 全文和结构化检索 |
| XLS | 通过转换层处理 | 全文和结构化检索 |
| PPTX | 提取幻灯片文本、备注和图片文字 | 全文和向量 |
| PPT | 通过转换层处理 | 全文和向量 |
| JSON、YAML、XML | 保留字段路径和值 | 全文和向量 |
| PNG、JPG、WEBP | OCR，必要时使用视觉模型描述 | OCR文本和向量 |
| 音频 | 语音转写 | 转写文本和向量 |
| 视频 | 音频转写，必要时提取关键帧 | 转写文本和向量 |
| ZIP、RAR | 解压后分别处理内部文件 | 取决于内部文件 |
| EXE 和其他二进制 | 保存元数据并标记不支持 | 不建立正文索引 |

### 6.1 旧版 Office 文件

`.doc`、`.xls`、`.ppt` 是旧版二进制格式，不能直接按 XML 解析。推荐使用 LibreOffice headless 转换：

```text
.doc/.xls/.ppt
→ LibreOffice headless
→ .docx/.xlsx/.pptx 或 HTML/TXT
→ 统一解析器
```

要求：

- 转换使用临时目录。
- 不修改原文件。
- 保留原始路径和扩展名。
- 尽量保留标题、段落、表格和页码。
- 单个文件转换失败不阻塞整个数据源。
- 密码保护文件标记为 `password_required`。
- 转换失败标记为 `failed` 并保存原因。

### 6.2 统一中间结构

解析器将文件转换为统一结构，例如：

```json
{
  "source_path": "/合同/采购合同.doc",
  "title": "采购合同",
  "text": "合同正文文本……",
  "sections": [],
  "tables": [],
  "images": [],
  "pages": 12,
  "metadata": {
    "filename": "采购合同.doc",
    "modified_at": "2026-09-22T10:00:00"
  }
}
```

表格不能简单拼接成一大段文本，应保留表头、行列关系和工作表位置。

## 7. 提取模板

提取模板是企业级资源，不属于单独的知识库。

### 7.1 模板内容

模板可以定义：

- 内容摘要。
- 关键词数组。
- 文档类型。
- 日期。
- 金额。
- 合同主体。
- 编号。
- 项目负责人。
- 枚举和自定义字段。
- 字段类型和必填状态。
- 字段提取说明。
- 整体提取指令。
- 适用的文件类型。

示例：

```json
{
  "name": "合同信息提取模板",
  "fields": [
    {
      "name": "summary",
      "type": "text",
      "required": true,
      "instruction": "用不超过300字总结合同核心内容"
    },
    {
      "name": "keywords",
      "type": "string[]",
      "required": true,
      "instruction": "提取5到15个核心关键词"
    },
    {
      "name": "effective_date",
      "type": "date",
      "required": false,
      "instruction": "提取合同生效日期"
    }
  ],
  "instruction": "重点关注合同主体、期限、金额、付款和违约责任。"
}
```

### 7.2 模板生命周期

模板新建流程：

```text
填写模板
→ 配置字段
→ 选择测试文件
→ 试运行提取
→ 校验结构化输出
→ 保存为新版本
```

模板管理规则：

- 系统管理员可以管理全部模板。
- 企业管理员可以管理本企业模板。
- 员工默认只能使用已绑定模板。
- 模板支持新建、编辑、测试、停用和删除。
- 已被使用的模板不能直接物理删除。
- 模板停用后不能绑定到新数据源。
- 已有提取结果保留历史模板版本。

### 7.3 模板版本

编辑模板时生成新版本，不直接覆盖历史结果：

```text
合同模板 v1
├── 文件 A 使用
└── 文件 B 使用

编辑模板
↓
生成合同模板 v2
↓
管理员选择是否批量重提取
```

每条提取结果记录：

- 模板 ID。
- 模板版本。
- 模型 ID。
- 解析器版本。
- 文件 hash。
- 提取时间。
- 处理状态。

模板更新后默认不自动处理全部文件。管理员可以按文件、目录或数据源批量重提取。

### 7.4 模板绑定

模板可以绑定到：

```text
数据源
└── 目录
    └── 单个文件
```

匹配优先级：

```text
文件级
> 目录级
> 数据源级
```

绑定条件支持：

- 文件夹路径。
- 文件扩展名。
- MIME 类型。
- 文件名模式。
- 正则表达式。
- 文件类型。

同一层级匹配多个模板时必须提示冲突，不能随机选择。

前端需要支持：

- 新建、编辑、停用模板。
- 测试模板。
- 查看模板版本和使用情况。
- 设置数据源默认模板。
- 给目录或文件覆盖模板。
- 清除覆盖并恢复继承。
- 批量重新提取。
- 查看模板冲突和处理状态。

## 8. 文件同步和处理任务

### 8.1 混合同步

```text
文件事件监听 → 快速发现变化
定时扫描 → 修正漏报和网络异常
手动同步 → 管理员立即触发
完整扫描 → 最终一致性校准
```

SMB/NFS 的实时事件可能因为断线、NAS 能力或批量复制而丢失，所以事件监听不能作为唯一事实来源。

扫描比较：

- 文件路径。
- 文件大小。
- 修改时间。
- 内容 hash。
- 当前模板版本。
- 解析器版本。
- 向量模型版本。

只有发生变化时才重新处理文件。

### 8.2 文件状态

```text
discovered
processing
ready
failed
deleted_pending
deleted
permission_denied
unavailable
password_required
unsupported
```

### 8.3 变化行为

| 文件变化 | 处理行为 |
| --- | --- |
| 新增 | 根据最具体的模板绑定提取并建立索引 |
| 修改 | 保留旧结果，新结果成功后原子替换 |
| 删除 | 先进入待确认状态，确认后从搜索结果移除 |
| 权限变化 | 重新计算文件可见范围 |
| 网络暂时断开 | 保留上次成功结果并标记数据源异常 |
| 模板版本变化 | 标记结果过期，等待批量重提取 |

文件复制过程中增加防抖，确认大小和修改时间稳定后再处理。

删除默认保留短暂确认期，防止网络共享临时断开造成误删。删除确认后：

- 文件不再参与搜索。
- 文件不再注入对话。
- 保留同步日志和删除记录。

### 8.4 提取任务

每次提取都是可追踪任务：

```text
待处理
处理中
成功
失败
等待重试
已取消
```

支持：

- 单文件重新提取。
- 文件夹批量提取。
- 数据源批量提取。
- 只重新提取失败文件。
- 只重新提取模板版本过期文件。
- 取消尚未开始的任务。
- 查看失败原因和重试任务。

## 9. 搜索与向量模型

向量模型不是文件解析器，也不是知识整理器。它主要完成：

```text
文本分块
→ 向量模型
→ 数字向量
→ 相似度检索
```

三类检索能力：

- 关键词搜索：适合编号、姓名、型号和精确词语。
- 全文搜索：适合原文匹配。
- 向量搜索：适合语义相近但措辞不同的查询。

摘要、关键词和结构化字段提取不依赖向量模型。建议先实现文件解析、结构化提取和全文搜索，再接入向量模型。

最终采用混合检索：

```text
关键词匹配
+ 全文匹配
+ 向量匹配
+ 企业范围过滤
+ 文件夹/文件权限过滤
```

## 10. 企业级存储资源池

存储后端与知识库暂时解耦，主要服务 Agent 工作区和平台资源。

规则：

- 系统管理员配置存储后端。
- 一个存储后端只绑定一个企业。
- 后端支持用户、部门和角色级访问授权。
- `storage_backends` 控制存储配置管理。
- 后端级 ACL 控制具体使用权限。
- `enabled=false` 只禁止新的 Agent 绑定。
- 已绑定 Agent 暂不立即中断，保证兼容性。
- 删除前必须检查 Agent 引用。

后续可增加：

- 企业和部门配额。
- 存储使用统计。
- 访问审计。
- 后端迁移。
- 目录前缀隔离。

知识库是否未来使用存储后端保存原始文件，作为后续独立架构决策，不与本阶段外部文件夹索引强行合并。

## 11. API 与前端方向

知识库 API 不再以“创建/删除知识库”为中心，而应围绕企业知识空间提供：

- 获取当前企业知识库。
- 管理数据源。
- 测试 SMB/NFS 连接。
- 扫描和同步数据源。
- 查询文件索引和处理状态。
- 管理目录和文件权限。
- 管理提取模板。
- 管理模板版本。
- 管理模板绑定。
- 单文件或批量重提取。
- 搜索当前用户有权限的内容。
- 查看摘要、关键词和结构化字段。
- 访问被授权的原文件。

前端页面建议包括：

- 企业知识库总览。
- 数据源管理。
- 文件树和文件状态。
- 文件/目录权限管理。
- 提取模板管理。
- 模板测试和版本记录。
- 模板绑定关系。
- 同步任务和失败记录。
- 搜索与结果引用。

## 12. 实施阶段

1. 企业知识空间和数据源基础模型。
2. SMB/NFS 连接、加密凭据和连接测试。
3. 文件扫描、hash、变化检测和任务状态。
4. TXT、MD、PDF、DOC、DOCX、XLS、XLSX、CSV 等解析。
5. OCR、旧版 Office 转换和统一文档结构。
6. 摘要、关键词和自定义字段提取。
7. 模板 CRUD、测试、版本和绑定。
8. 企业、部门、用户和角色级文件权限。
9. 全文搜索和原文件引用。
10. 向量模型、分块和混合检索。
11. 企业级存储后端和后端级 ACL。
12. 配额、审计、迁移和高级同步能力。

## 13. 数据迁移原则

- 保留现有 `knowledge_bases` 权限键，调整其语义。
- 旧的用户知识库数据需要迁移到对应企业知识空间。
- 旧上传文件可以作为一个兼容数据源导入。
- 不再允许新建多个用户知识库。
- 旧知识库的共享关系转换为企业、部门、用户或角色级文件/目录 ACL。
- 旧向量索引可以保留，但应记录其模型和版本。
- 数据迁移必须同时提供 SQLite 和 PostgreSQL 方案。

## 14. 测试与验收标准

### 数据源和同步

- 可以配置并测试 SMB/NFS 数据源。
- 新增、修改和删除文件能够同步。
- 文件复制未完成时不会提前处理。
- 网络短暂中断不会误删内容。
- 手动同步可以立即触发处理。
- 单个文件失败不会阻断整个数据源。

### 文件解析

- TXT、MD、PDF、DOC、DOCX、XLS、XLSX、CSV 能够处理。
- 扫描 PDF 和图片可以走 OCR。
- `.doc` 不修改原文件即可完成转换和解析。
- 密码文件和不支持文件有明确状态。
- 表格保留基本行列和位置关系。

### 模板

- 模板支持新建、编辑、测试、版本、绑定、停用和删除。
- 文件级规则优先于目录级，目录级优先于数据源级。
- 模板冲突会被识别，不会随机选择。
- 模板更新不会破坏历史提取结果。
- 可以按文件、目录和数据源批量重提取。

### 权限

- 一个企业只有一个逻辑知识库。
- 用户不能访问其他企业的知识内容。
- 部门权限默认覆盖子部门。
- 读取权限和编辑权限独立生效。
- 未授权内容不会出现在搜索、摘要、引用或下载中。
- 数据源连接账号权限和平台用户权限分别校验。

### 搜索

- 全文搜索和向量搜索可以独立启用。
- 搜索结果能够引用原文件路径及位置。
- 向量索引不会绕过文件权限。
- 文件重新处理后旧索引不会与新索引混用。

### 验收命令

```bash
make all
cd dashboard
npx tsc -b
```

## 15. 第一阶段不包含

- 不增加部署级全局模块开关。
- 不建立独立于统一权限模型的客户产品授权系统。
- 不把 `AgentCapability` 与用户功能权限合并。
- 不把知识库强制绑定到存储后端。
- 不在知识库重构中顺便重构无关的 Agent 工作区逻辑。
