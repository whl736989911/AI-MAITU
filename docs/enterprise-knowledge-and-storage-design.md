# 企业知识库与外部文件夹数据源

> 状态：已实现能力与边界说明；未实现的方向会明确标出。
>
> 关联文档：[定制化功能权限与组织管理设计](./customized-permissions-and-org-management.md)
>
> 本文描述企业知识库、外部文件夹数据源、文件权限、增量同步与多格式解析的当前通用行为。它不是客户特定的构建或验收记录。

## 1. 核心结论

知识库不设计为“用户新建多个知识库”，而是采用企业级单一知识库：

```text
企业
└── 企业知识库
    ├── 数据源文件夹
    ├── 文件索引
    ├── 全文索引
    └── 可选向量索引
```

核心规则：

- 每个企业只有一个逻辑知识库。
- 用户不能新建第二个知识库。
- 一个企业知识库可以绑定多个本地或 SMB 文件夹；NFS 连接器不属于当前支持范围。
- 平台上传件保存在平台存储；源上传件写入登记的本地/SMB 目录，原始文件由其目标位置保存。
- 用户能看到和搜索到的内容由企业、部门、用户和角色权限决定。
- 知识库读取权限和编辑权限分离。
- 本地/SMB 数据源可手动扫描，也可按正的 `scan_interval_seconds` 定时扫描；`0` 表示关闭。
- 向量模型是可选的语义检索能力，不负责文件解析和知识整理本身。

如果系统是单企业部署，则平台只有一个企业知识库；如果系统未来支持多企业，则每个企业拥有独立的逻辑知识库和数据权限边界。

### 已实现的通用文件检索

知识库启用后无需向量模型即可按文件名和正文词项检索；可选配置向量模型，作为语义召回补充。上传或同步文件时，目录扫描先登记变更，后台限流解析并建立持久化段落/词项索引；重启后未完成的任务继续处理。新建企业知识库默认不限制文件数量；已有知识库保留原有上限，可在知识库设置中调整（0 表示不限）。

PDF 按页、Word 按段落/表格行、演示文稿按幻灯片、表格按工作表/行、文本按行保留定位。搜索先限定用户可读的文件，再排序和截取结果；`GET /api/knowledge-bases/{kb_id}/coverage` 返回可读文件、可搜索文件以及待处理/失败/不支持数量。`GET /api/knowledge-bases/{kb_id}/search?q=…` 返回带 `segment_id`、位置和原文件版本的命中；`GET /api/knowledge-bases/{kb_id}/documents/{doc_id}/segments/{segment_id}` 复核文件权限及原文件摘要，再返回定位原文。原文件变化或不可访问时不返回未核验的正文。

Agent 仅在本轮选中可读知识库时获得原件浏览、路径定位、整理集读取、原件按需读取与取得、图片观察记录工具。相关整理集的两份 Markdown 先于原件正文读取；无索引或向量模型也能读取有权限的原件。普通阅读按实际证据更新所有包含该文件的整理集，不在进入会话时预取整库正文。源文件、检索片段和整理文档都是参考数据，不是系统指令。

## 2. 当前架构

平台提供单一企业知识库，支持平台原件上传与已登记的本地/SMB 文件夹数据源。上传和扫描均进入同一解析、索引和权限过滤流程；源目录保存其原始文件，平台为检索保留索引与派生内容。NFS 连接器当前不可用。

```text
平台上传 / 本地或 SMB 数据源
→ 文件类型识别与实际可用解析器
→ 解析成功时建立词项索引及可选向量索引
→ 按当前库、目录和文件 ACL 过滤搜索、预览及原件访问
```

现有 `knowledge_bases` 权限标识可以暂时保留以兼容旧用户配置，但语义调整为“企业知识库访问/管理权限”，不再表示用户可以创建多个知识库。

## 3. 数据模型

建议将知识库相关对象拆成以下几类：

### 3.1 企业知识空间

```text
EnterpriseKnowledgeSpace
```

表示一个企业的唯一逻辑知识库。它不再有“用户所有者”概念，主要关联企业、状态、默认搜索策略和全局统计信息。

### 3.2 数据源

```text
KnowledgeSource
```

表示一个本地或网络文件夹连接，包含：

- 所属企业。
- 当前支持的数据源连接类型：`local`、`smb`；NFS 连接器不可用。
- 地址、共享名称和根目录。
- 加密后的凭据引用。
- 只读设置。
- 包含/排除规则。
- 扫描间隔。
- 连接状态。
- 最近扫描时间和最近成功同步时间。

### 3.3 文件索引

```text
KnowledgeFile
```

保存源文件的索引和处理状态：

- 数据源 ID。
- 相对路径和文件名。
- 扩展名、MIME 类型和检测到的真实类型。
- 文件大小、修改时间和内容 hash。
- 解析器版本。
- 当前模板和模板版本。
- 处理状态。
- 删除或不可访问状态。
- 原文件定位信息，例如页码、工作表和段落。

### 3.4 派生内容

```text
KnowledgeChunk
KnowledgeEmbedding
```

分别保存：

- 正文和统一文档结构。
- 文档分块。
- 全文索引。
- 可选向量索引。
- 文件版本及解析器版本。

原始文件是外部数据源的事实来源，平台不长期复制源原件。解析和下载可能使用请求期临时副本或经 SHA-256 校验的快照，完成后清理；平台上传的原件仍保存在平台存储中。

## 4. 数据源连接与安全

当前支持本地服务器目录与 SMB 共享目录；NFS 连接器当前不可用。数据源默认只读，连接账号拥有的存储权限不等于平台用户权限。

安全要求：

- 密码和密钥必须加密保存。
- API 不返回明文凭据。
- 日志不能打印凭据、完整连接字符串或授权头。
- 源上传必须显式将 `read_only` 设为 `false` 并启用上传；默认只读源不能接收上传。
- 平台连接账号拥有读取能力，不代表所有平台用户都拥有访问能力。
- 连接测试、扫描和文件读取都需要记录审计信息。


## 5. 权限模型

知识库内部权限不再围绕多个知识库之间的共享，而是围绕企业知识库内的资源：

```text
企业知识库
└── 数据源
    └── 文件夹
        └── 文件
```

### 5.1 授权主体

支持以下授权主体：

- 企业。
- 部门。
- 用户。
- 角色。

部门授权默认包含本部门及所有子部门。

### 5.2 读取和编辑分离

读取权限控制：

- 是否可以搜索文件。
- 是否可以查看原文件或原文件链接。
- 是否可以在对话中使用检索结果。

编辑权限控制：

- 是否可以添加或删除数据源。
- 是否可以修改目录权限。
- 是否可以触发数据源同步与文件重新索引。

搜索必须先过滤权限，再执行检索：

```text
用户身份
→ 企业范围
→ 数据源权限
→ 目录/文件权限
→ 搜索和摘要
→ 原文件访问
```

不能先搜索整个企业知识库，再在结果展示阶段过滤，否则摘要、引用和搜索片段可能泄露无权访问的内容。

### 5.3 目录权限继承

推荐采用目录继承：

```text
共享目录
├── 公司制度       → 全企业可读
├── 财务资料       → 财务部门可读
├── 人事资料       → 人事部门可读
└── 技术资料
    ├── 产品A       → 产品A小组可读
    └── 产品B       → 产品B小组可读
```

规则：

- 上级目录权限默认继承到子目录。
- 子目录有显式 ACL 时，与上级目录权限相交，默认只能逐级收窄；对子目录授权不能绕过上级目录。
- 文件默认继承所在目录权限。
- 只有单个文件上明确匹配用户、部门或角色的授权，才可作为目录限制的例外；“公开文件”本身不构成例外，文件自己的 ACL 与知识库权限仍须同时满足。
- 企业管理员管理本企业范围。
- 部门管理员管理本部门及子部门范围。
- 员工只能访问被授权的文件。
- 读取和写入分别计算；库级可写不代表受限文件可写，更新、删除、重新索引和数据源操作复用文件写权限。整库重新索引先检查全部目标，避免无权文件导致部分修改。
- 列表、覆盖统计、搜索、预览、下载、段落证据和 Agent 引用使用同一有效权限范围。例外授权仅暴露该文件，不暴露被拒绝的目录行、其他文件或它们的统计；已授权文件保留真实路径以支持定位和个人检索规则。
- 在现有「共享治理 → 共享设置 → 知识库目录与文件」中维护目录或文件的读取/编辑范围与用户、部门、角色授权，沿用审批、版本和审计流程；不另建一套权限系统。

底层 SMB/NFS 凭据权限和平台内部业务权限是两套权限，必须分别校验。平台授权不改写源目录的操作系统或 SMB ACL，也不能撤回用户已下载的副本；源系统仍需独立配置访问范围和备份。

### 5.4 已实现的上传授权和逐级转授权

平台上传和源文件夹上传都先获取目标位置的可授权上限，再选择公司、部门、个人或当前自定义授权范围及读写级别。默认选择服务器计算的最大范围；上传时再次校验，初始 ACL 与文件索引行在同一事务创建。仅凭单独个人授权进入目标目录的用户只能选择个人范围，不能借上传扩散资料。复杂角色/部门授权保存当前可授予用户的快照，不继承父目录未来的扩权。

对单独用户授权可显式开启“允许转授权”，默认关闭。开关只授予该文档的转授权能力，不授予修改原始 ACL、修改别人的授权或绕过知识库权限的能力。每一跳沿用授权者当前有效的读写上限；自授权和环路被拒绝，单个文件的授权不泄露同级文件。

接收者必须同时拥有知识库基础访问权；调出授权部门等导致该权限失效时，残留的文档转授权不会让知识库继续出现在列表，也不能用于读取、下载或检索文件。

撤销根授权、关闭转授权或撤销中间边时，在同一事务删除失去有效来源的派生边；独立有效授权保留，重新打开开关不会恢复已删除的下游链。直接个人授权即使从未允许转授权，撤销时也会通知原接收者。

撤销通知持久化保存资源的逻辑路径及撤销后是否仍有有效读取权限，页面全局通知栏可查看并标记已读。通知仅本人可读，不要求继续拥有知识库或知识库模块权限；实例授权门禁仍然适用。权限撤销不代表能追回已经下载到平台外的文件副本。


## 6. 文件类型与统一解析

向量模型主要接收文本或结构化文本，不能直接处理 PDF、Word、Excel、图片等文件。统一流程为：

```text
文件类型识别
→ 对应解析器/OCR/转写器
→ 统一文档结构
→ 文本分块
→ 全文索引和可选向量索引
```

支持矩阵：

| 文件类型 | 处理方式 | 后续检索 |
| --- | --- | --- |
| TXT、MD、HTML | 直接读取文本 | 全文和向量 |
| PDF | 提取文本；扫描 PDF 使用 OCR | 全文和向量 |
| DOCX | 直接读取包内文本 XML，提取正文、标题、表格和批注，不加载无关图片数据 | 全文和向量；内嵌图片不自动 OCR |
| DOC | 使用可用转换器解析 | 全文和向量；缺少转换能力时明确失败 |
| XLSX、CSV | 保留表头、行列和单元格关系 | 全文和结构化检索 |
| XLS | 通过转换层处理 | 全文和结构化检索 |
| PPTX | 提取幻灯片文本、备注和图片文字 | 全文和向量 |
| PPT | 通过转换层处理 | 全文和向量 |
| JSON、YAML、XML | 保留字段路径和值 | 全文和向量 |
| PNG、JPG、WEBP | OCR，必要时使用视觉模型描述 | OCR文本和向量 |
| 音频 | 语音转写 | 转写文本和向量 |
| 视频 | 音频转写，必要时提取关键帧 | 转写文本和向量 |
| ZIP、RAR | 解压后分别处理内部文件 | 取决于内部文件 |
| DWG、DXF | 可选 CAD CLI 解析文字实体；不生成完整 CAD 渲染或几何推断 | 仅解析出的文字证据可预览和检索；工具缺失或无文本时不冒充可搜索 |
| 其他未知格式/二进制 | 两种上传目的地均可保存原件；若无真实解析器则标记 archive-only/unsupported | 不建立正文索引 |

### 6.1 处理器能力与 CAD 文本解析

`GET /api/knowledge-bases/processors` 返回当前处理器能力，包括内置格式和可选 CAD 命令的实际可用状态。旧版 Office 转换器通过 `OCTOP_LIBREOFFICE_PATH` 指定；LibreDWG 读取器通过 `OCTOP_LIBREDWG_DWGREAD` 指定。未配置或不可用时，文件不能报告为已解析或可搜索。

DWG/DXF 原件保持不变；CAD 适配器提取可解析的 TEXT/MTEXT、图层、布局、句柄及坐标作为文本证据，用于文本预览与索引。它不是完整 CAD 图形渲染器，也不推断几何尺寸。仅能保存原件时明确标记 archive-only/unsupported，不伪造正文索引。

仅归档是已完成的处理状态：源文件未变化时不反复进入索引队列。安装或启用缺失的处理器后可手动重建索引。本轮未增加音视频转写或压缩包解包；没有真实处理器的文件保留原件，不生成虚假的正文或检索证据。

### 6.2 旧版 Office 文件
`.doc`、`.xls`、`.ppt` 是旧版二进制格式，不能直接按 XML 解析。推荐使用 LibreOffice headless 转换：

```text
.doc/.xls/.ppt
→ LibreOffice headless
→ .docx/.xlsx/.pptx 或 HTML/TXT
→ 统一解析器
```

要求：

- 转换使用临时目录。
- 不修改原文件。
- 保留原始路径和扩展名。
- 尽量保留标题、段落、表格和页码。
- 单个文件转换失败不阻塞整个数据源。
- 密码保护文件标记为 `password_required`。
- 转换失败标记为 `failed` 并保存原因。

### 6.3 统一中间结构

解析器将文件转换为统一结构，例如：

```json
{
  "source_path": "/合同/采购合同.doc",
  "title": "采购合同",
  "text": "合同正文文本……",
  "sections": [],
  "tables": [],
  "images": [],
  "pages": 12,
  "metadata": {
    "filename": "采购合同.doc",
    "modified_at": "2026-09-22T10:00:00"
  }
}
```

表格不能简单拼接成一大段文本，应保留表头、行列关系和工作表位置。

### 6.4 8 GiB 实例的索引资源控制

- 一个进程同一时间只执行一个文档的解析/索引任务；后台任务与同步 URL、上传数据源共用限制，不再分别叠加重型处理。
- 内置 PDF OCR 使用一个 MuPDF 文档，按页提取文本，仅对无文本页 OCR；不通过 pypdf 文本提取累积缓存每页的压缩图片流，不截断几百页文档。
- 每页 OCR 渲染不超过 144 dpi、最长边 2,000 像素、总像素 400 万；本地推理直接接收像素数组，不进行 PNG 编码再解码。远程视觉 OCR 同样使用受限图片。
- 本地 OCR 的 ONNX 推理限制为 2 个算子内线程、1 个算子间线程，OpenCV 限制为 1 个线程。文档中的小字可能因分辨率上限降低识别率，需用实际文件检验质量。
- 词项与索引行逐段生成，可选嵌入每批最多 20 个分块并在事务中替换；本地嵌入限制 2 个线程，模型实例复用、串行推理，切换前释放旧实例。索引数据库连接在事务结束后立即关闭。
- 文本预览最多返回 200,000 字符，优先读取完成的索引并复核原文件 hash，不重新解析或 OCR；未索引的本地 Markdown/TXT 可有限读取，其他未完成或过期索引返回 `KNOWLEDGE_INDEX_NOT_READY`（409）。
- 纯图片 DOCX 仍没有可检索正文；当前不新增其内嵌图片 OCR，可将此类文件转为 PDF 后使用已有 PDF OCR。
- 这些是进程内资源控制，不是操作系统级内存硬隔离；文本规模、原始大图解码、所选模型及同机服务仍影响峰值。8 GiB 部署建议单服务进程并预留系统与业务内存，多 worker 会分别持有模型、叠加任务峰值；不应据此假定可同时运行大内存本地 LLM。


## 7. 文件检索

普通搜索支持已成功解析并建立索引的文件；词法检索不依赖向量模型，语义召回可选。搜索与预览都先按调用者当前知识库、目录和文件 ACL 限定范围。仅归档保存、未支持或未完成解析的文件不产生正文搜索结果。

## 8. 文件同步和处理任务

### 8.1 手动与定时扫描

本地/SMB 数据源支持手动扫描和按配置间隔定时扫描。通过 `PATCH /api/data-sources/{ds_id}` 的 `folder.scan_interval_seconds` 设置：`0` 关闭定时扫描，正数设置两次尝试的最小间隔。调度器每 15 秒检查到期源；新建或变化的文件须通过已有 30 秒稳定观察窗口后进入后台索引队列，不是实时文件事件监听。`GET /api/data-sources/{ds_id}/runs` 保留 scheduled trigger、成功或失败及实际计数。停机先等待扫描和在途索引线程结束，再关闭数据库；尚未执行的索引保持待处理状态供下次启动恢复。

扫描比较：

- 文件路径。
- 文件大小。
- 修改时间。
- 内容 hash。
- 当前模板版本。
- 解析器版本。
- 向量模型版本。

只有发生变化时才重新处理文件。

### 8.2 文件状态

```text
discovered
processing
```

### 8.3 变化行为

| 文件变化 | 处理行为 |
| --- | --- |
| 新增 | 按文件类型解析并建立索引 |
| 修改 | 保留旧结果，新结果成功后原子替换 |
| 删除 | 先进入待确认状态，确认后从搜索结果移除 |
| 权限变化 | 重新计算文件可见范围 |
| 网络暂时断开 | 保留上次成功结果并标记数据源异常 |

文件复制过程中增加防抖，确认大小和修改时间稳定后再处理。

删除默认保留短暂确认期，防止网络共享临时断开造成误删。删除确认后：

- 文件不再参与搜索。
- 文件不再注入对话。
- 保留同步日志和删除记录。

## 9. 搜索与向量模型

向量模型不是文件解析器，也不是知识整理器。它主要完成：

```text
文本分块
→ 向量模型
→ 数字向量
→ 相似度检索
```

三类检索能力：

- 关键词搜索：适合编号、姓名、型号和精确词语。
- 全文搜索：适合原文匹配。
- 向量搜索：适合语义相近但措辞不同的查询。

文件解析和全文搜索不依赖向量模型。先解析文件和建立全文索引，再按需配置语义向量。

已有正文索引的普通搜索保留词法匹配与可选向量召回，统一按当前知识库、文件夹和文件权限过滤；它不是 Agent 访问原件的前提。

此前的个人关键词别名、文件/目录 `hybrid`、`keyword`、`exclude` 策略及 `/search-rules` 接口已移除。当前采用来源权限共享的资料整理集：

- 创建时只登记文件或目录范围及用户提示词，不自动解析文件。
- 点击「整理」按提示词生成专题成果；普通实际阅读积累到另一份 Markdown，并记录源路径、具体位置和版本。
- Agent 先读相关专题与阅读积累，再根据出处读取原件；同一源文件的一次读取同步到所有包含它的整理集。
- 整理集及派生内容按当前源权限过滤；修改提示词、主动整理和删除要求源写权限或知识库管理权限。

完整交互、存储和证据约束见 [原件访问与双文档方案](knowledge-processing-development-plan.md)。

## 10. 企业级存储资源池

存储后端与知识库暂时解耦，主要服务 Agent 工作区和平台资源。

规则：

- 系统管理员配置存储后端。
- 一个存储后端只绑定一个企业。
- 后端支持用户、部门和角色级访问授权。
- `storage_backends` 控制存储配置管理。
- 后端级 ACL 控制具体使用权限。
- `enabled=false` 只禁止新的 Agent 绑定。
- 已绑定 Agent 暂不立即中断，保证兼容性。
- 删除前必须检查 Agent 引用。

后续可增加：

- 企业和部门配额。
- 存储使用统计。
- 访问审计。
- 后端迁移。
- 目录前缀隔离。

知识库是否未来使用存储后端保存原始文件，作为后续独立架构决策，不与本阶段外部文件夹索引强行合并。

## 11. API 与前端方向

知识库 API 不再以“创建/删除知识库”为中心，而应围绕企业知识空间提供：

- 获取当前企业知识库。
- 管理数据源。
- 测试 SMB/NFS 连接。
- 扫描和同步数据源。
- 查询文件索引和处理状态。
- 管理目录和文件权限。
- 搜索当前用户有权限的内容。
- 查看文档标题、位置和索引覆盖情况。
- 访问被授权的原文件。

前端页面建议包括：

- 企业知识库总览。
- 数据源管理。
- 文件树和文件状态。
- 文件/目录权限管理。
- 同步任务和失败记录。
- 搜索与结果引用。

## 13. 数据迁移原则

- 保留现有 `knowledge_bases` 权限键，调整其语义。
- 旧的用户知识库数据需要迁移到对应企业知识空间。
- 旧上传文件可以作为一个兼容数据源导入。
- 不再允许新建多个用户知识库。
- 旧知识库的共享关系转换为企业、部门、用户或角色级文件/目录 ACL。
- 旧向量索引可以保留，但应记录其模型和版本。
- 数据迁移必须同时提供 SQLite 和 PostgreSQL 方案。

## 14. 测试与验收标准

### 数据源和同步

- 可以配置并测试 SMB/NFS 数据源。
- 新增、修改和删除文件能够同步。
- 文件复制未完成时不会提前处理。
- 网络短暂中断不会误删内容。
- 手动同步可以立即触发处理。
- 单个文件失败不会阻断整个数据源。

### 文件解析

- TXT、MD、PDF、DOC、DOCX、XLS、XLSX、CSV 能够处理。
- 扫描 PDF 和图片可以走 OCR。
- `.doc` 不修改原文件即可完成转换和解析。
- 密码文件和不支持文件有明确状态。
- 表格保留基本行列和位置关系。

### 个人检索策略

- 用户可配置有权读取的目录和单个文件，不需要知识库写入权限。
- 文件规则优先于最近上级目录；清除覆盖后恢复继承，其他用户的设置不受影响。
- 排除规则不会返回文件；关键词规则只返回未验证的文件候选，不绕过文件权限。
- 三种检索模式在选择时提供悬停说明。

### 权限

- 一个企业只有一个逻辑知识库。
- 用户不能访问其他企业的知识内容。
- 部门权限默认覆盖子部门。
- 读取权限和编辑权限独立生效。
- 未授权内容不会出现在搜索、预览、引用或下载中。
- 受限目录中的公开文件仍被拒绝；单文件明确授权只放行该文件且不突破知识库 ACL，子目录授权不能构成祖先目录例外。
- 数据源连接账号权限和平台用户权限分别校验。

### 搜索

- 全文搜索和向量搜索可以独立启用。
- 搜索结果能够引用原文件路径及位置。
- 向量索引不会绕过文件权限。
- 文件重新处理后旧索引不会与新索引混用。

### 验收命令

```bash
make all
cd dashboard
npx tsc -b
```

## 15. 第一阶段不包含

- 不增加部署级全局模块开关。
- 不建立独立于统一权限模型的客户产品授权系统。
- 不把 `AgentCapability` 与用户功能权限合并。
- 不把知识库强制绑定到存储后端。
- 不在知识库重构中顺便重构无关的 Agent 工作区逻辑。
